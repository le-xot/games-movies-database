# Архитектурная уборка

Кампания по систематическому снижению архитектурной энтропии. Не редизайн ради редизайна:
цель — код, в котором новая фича делается в одном месте, а не в пяти, и который можно уверенно
править несколькими агентами параллельно.

## Цель кампании

1. **Single Source of Truth** — у каждого правила, типа, конфига и состояния ровно один источник.
2. **Canonical implementation** — одна семантика = одна реализация; параллельных путей нет.
3. **Deep modules** — сложность внутри, наружу простой и стабильный интерфейс.
4. **High cohesion, low coupling** — явные границы, один направленный поток зависимостей.
5. **Locality of change** — правка одного бизнес-концепта не растекается по десятку файлов.
6. **Deletion over accumulation** — новая реализация входит вместе с удалением старой.
7. **Enforceable architecture** — принятые нормы защищены машиной (типы, lint, тесты, CI).

## Правила игры

1. **Батч = законченная миграция.** Новый канон + перевод всех вызовов + удаление старого.
   Запрещено оставлять «временные» параллельные пути и «уберём позже».
2. **Внешние контракты неизменны.** HTTP-роуты, коды и конверт ошибок, WS-события и их
   payload'ы, cookie `token`, формат данных в БД, env-контракт, публичные команды bun.
   Ломать можно только внутренние контракты (импорты модулей, внутренние типы, имена).
3. **Зоны повышенной осторожности** (решение владельца): деплой/CI/Docker, схема БД и
   миграции, auth/OAuth/Telegram, WS-протокол. Меняем только при явной выгоде, без смены
   механики; миграции — только через `bun db:generate`.
4. **Порядок батча**: baseline тестов → изменение → `bun lint && bun format:check &&
   bun typecheck` + unit-тесты → независимое ревью **новым агентом** (не автором изменения) →
   commit.
5. **Каждая устранённая регрессия получает ловушку** — тест, lint-правило, type-level
   проверку или CI-шаг. Уборка без защиты считается недоделанной.
6. **Deletion test.** Если удаление абстракции не увеличивает сложность вызывающих — абстракция
   удаляется. Оставлять её «на всякий случай» запрещено.
7. **Не изобретать проблемы.** Нет высокоценной задачи — батч не начинается. Мелочи не
   подменяют системные улучшения.

## Definition of done для батча

- [ ] старый путь удалён, вызовов не осталось
- [ ] нет новых `any`, `as unknown as`, `eslint-disable`
- [ ] существующие тесты зелёные, на новый канон есть тест
- [ ] `bun lint`, `bun format:check`, `bun typecheck` зелёные
- [ ] независимое ревью пройдено (отчёт ревьюера приложен к задаче/коммиту)
- [ ] задачи, карты и ADR обновлены
- [ ] commit: `refactor(<area>): <что канонизировано>`

## Как читать карты

`maps/*.md` — снимок реального кода на момент рекона: структура, поток зависимостей, владение
состоянием, дубли, расхождения с `docs/architecture.md`. Карты устаревают; при закрытии батча
соответствующий раздел карты обновляется.

## Журнал решений

ADR пишется, когда решение меняет границы или норму (а не когда просто чиним дубль).
Формат — `adr/NNNN-краткое-имя.md`: контекст → решение → альтернативы → последствия.
