# 0004 — Схемы перечислений из контракта через `t.Enum`

## Контекст

Значения перечислений были объявлены трижды: в `@gmdb/contract`, в `pgEnum` и
литералами в TypeBox-схемах гейтвея. Забытый литерал в схеме ответа даёт 500 на
валидном доменном значении, а расхождение множеств не ловил ни typecheck, ни тест.

## Решение

- Значения объявлены один раз — словарями в `contract/src/enums.ts`
  (`const RecordGenre = { ... } as const` + одноимённый union-тип).
- TypeBox-схемы гейтвея строятся штатным `t.Enum(dictionary)`: TypeBox собирает
  union литералов и сохраняет литеральный тип, поэтому типы Eden не деградируют
  до `string`. `pgEnum` получает те же значения (`Object.values`).
- Инвариант держит `gateway/__tests__/enum-sources.spec.ts`: TypeBox-модель,
  `pgEnum` и контракт обязаны совпадать по множеству значений. Порядок
  `RecordStatus` в Postgres исторический (миграции не переупорядочивают
  значения) — тест фиксирует это явно, порядок отображения задаёт контракт.

Добавление значения — одна правка в контракте (плюс миграция, если меняется
`pgEnum`); тест подскажет забытые места.

## История: `enumUnion` удалён

Сначала здесь был самодельный `enumUnion(values)`: `t.Literal` для каждого
значения → `t.Union`, с приведением результата к tuple и кастом `value as Value`.
Причина каста — сохранение литерального типа; в ADR это было записано как
«массив деградирует `static` до `string`».

При разборе (после кампании) выяснилось:

1. `t.Enum` — штатный API TypeBox, внутри делает ровно то же
   (`Object.values → t.Literal → t.Union`), без кастов и tuple.
2. JSON-схемы `enumUnion(X)` и `t.Enum(X)` идентичны (включая словари из одного
   значения, где union сворачивается в `const`).
3. Typescript-типы `static`/Eden при `t.Enum` те же — литеральный union,
   посторонние значения не принимаются; проверено отдельными type-пробами.
4. Причина исходной проблемы — потеря литерального типа при ручной сборке
   литералов, а не «массив против tuple»; tuple-каст был ложным следствием.

`enumUnion` удалён, гейтвеи используют `t.Enum` напрямую. Тест и `pgEnum`
не менялись.

## Альтернативы

1. **Оставить литералы + тест на совпадение.** Дублирование остаётся, новый
   жанр/статус требует правок в трёх местах.
2. **Самодельный хелпер над `t.Union`.** Отклонено: лишний слой, нестандартный
   API, требует объяснений в ADR (см. историю выше).

## Последствия

- 17 мест схем собираются из контракта; ролевые константы гейтвеев используют
  `UserRole.*`.
- В `backend/src` больше нет собственных обёрток над TypeBox-перечислениями.
