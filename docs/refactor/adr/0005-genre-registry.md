# 0005 — Реестр жанров вместо знаний о жанре в 10 файлах

## Контекст

Новый жанр требовал правок в одиннадцати местах: маршрут, `switch` в `MediaPage`,
префетч, query-ключи, WS-обработчики, меню, статистика, карточка советов, палитра
команд, плюс два файла composables. Часть мест тихо деградировала: новый жанр
получал пустую страницу без префетча и инвалидации.

## Решение

`frontend/src/lib/genre-registry.ts` — единственное описание жанра: `genre`,
`path`, `routeName`, `label`, `icon`, `hasEpisodeColumn`, `deleteConfirmTitle`,
`queryKey`, `prefetch` (динамический импорт стора). Объект закрыт
`satisfies Record<RecordGenre, GenreEntry>`, поэтому жанр из контракта без записи
не скомпилируется.

Порядки объявлены там же: `GENRES` (канон для статистики), `NAV_GENRES` (меню),
`SUGGESTION_GENRES` (лента советов). Маршруты генерируются из реестра; `MediaPage`
получает метаданные оттуда, сторы — из `pages/media/genre-stores.ts`.

## Альтернативы

1. **Статические импорты сторов в реестре.** Цикл `registry → store → query-keys →
   registry`. Разорван листовым модулем `lib/genre-keys.ts` и отдельной картой
   `genre-stores.ts`.
2. **Динамический импорт сторов в `MediaPage`.** Откладывал бы стор на кадр и давал
   мигание скелетона; оставлен только для префетча.

## Последствия

- Новый жанр = запись в реестре + строка в `genre-stores` + контракт/БД; роутер,
  меню, WS, статистика и советы правок не требуют.
- WS-обработчики собираются из реестра (`composables/ws-handlers.ts`), полнота
  ключей проверяется тестом; `COALESCER_KEYS` — единый список и для ресинка.
- Ловушки: `genre-registry.spec.ts` (полнота, уникальность путей/имён/ключей),
  `ws-handlers.spec.ts` (каждый ключ имеет обработчик).
