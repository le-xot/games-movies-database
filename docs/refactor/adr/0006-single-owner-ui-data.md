# 0006 — Один владелец у сквозных UI-данных: заголовок, словарь, хранилище

## Контекст

Три вида сквозных данных были размазаны по файлам и синхронизировались вручную:

- `document.title` ставили семь мест (страницы через `@vueuse`, стор, навигация),
  из-за чего back/forward и прямые заходы давали устаревший заголовок;
- статусы и оценки имели имя в бейджах, hex-цвет в статистике, порядок в трёх
  списках, а `MediaCard` выводил `border-` из `bg-` строковым `replace`;
- ключи `localStorage` были литералами, а `main.ts` чистил чужие ключи по строкам.

## Решение

- **Заголовок**: `stores/use-title.ts` — единственный писатель; `router.afterEach`
  берёт `meta.title` (для главной — `titleSuffix: false`). Динамическое
  «Оценки {login}» остаётся в `use-user-ratings`, потому что зависит от данных.
- **Словарь**: `lib/record-vocabulary.ts` — name/label/description/tone (hex) и
  литеральные `badgeClass`/`borderClass`; `satisfies Record<RecordStatus|RecordGrade, …>`.
  Порядки — `STATUS_REPORT_ORDER`, `GRADE_REPORT_ORDER`, `GRADE_BUTTON_ORDER`.
- **Хранилище**: `lib/storage-keys.ts` — все ключи и `VERSIONED_STORAGE_KEYS`;
  строковые литералы ключей запрещены (проверяется сканом исходников).

## Альтернативы

1. **Оставить писателей, но синхронизировать документацией.** Ни один из трёх
   дублей не ловился тестом; документация не защищает.
2. **CSS-переменные для цветов статусов вместо литеральных классов.** Tailwind 4
   не увидит класс, собранный из переменной; литералы оставлены в одном файле.

## Последствия

- Серверный SEO-заголовок (`backend/src/server/page-meta.ts`) не затронут — это
  отдельный слой для краулеров; клиентский title от него не зависит.
- Ловушки: `use-title.spec.ts` (формат), `record-vocabulary.spec.ts` (полнота,
  tone ↔ class, порядки), `storage-keys.spec.ts` (уникальность, подмножество
  версионных ключей, запрет литералов в исходниках).
- Динамический заголовок оценок — единственное явное исключение, записано здесь,
  чтобы его не приняли за забытого второго писателя.
