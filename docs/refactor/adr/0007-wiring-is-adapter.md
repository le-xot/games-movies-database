# 0007 — Порт остаётся границей; `wiring/` — адаптер, а не маппер DTO

## Контекст

`docs/architecture.md` обещал, что `server/wiring/*` маппит сущности в DTO.
Фактически два из шести файлов были чистым pass-through, в остальных маппинга
не было — форму ответа держал рантайм-валидатор Elysia (TypeBox отбрасывает
лишние поля). При этом в домене осталось презентационное форматирование:
`queue.service` форматировал дату через `toLocaleDateString('ru-RU')`.

Выбор стоял между «добавить в порты явный `toDto`» и «удалить `wiring/`».

## Решение

- **Порты остаются.** Они — граница, через которую гейтвей знает только
  интерфейсы (`QueueReader`, `LikesService`, …) и не импортирует доменные
  сервисы; это проверяет `__tests__/architecture.spec.ts`.
- **`wiring/` — адаптер, а не маппер DTO.** Его задача — превратить доменный
  результат в форму порта: presentation-конверсии (даты, локаль) и адаптация
  сигнатур. Форму ответа на проводе по-прежнему держит TypeBox-схема.
- **Презентационное форматирование уходит из домена.** `QueueService` отдаёт
  ISO-строки (`queue.entity.ts`), человеческую дату ставит
  `server/wiring/analytics.ts`; class-DTO `queue.dto.ts` удалён.

## Альтернативы

1. **Удалить `wiring/` и типизировать гейтвей доменными типами.** Гейтвей начал
   бы импортировать сервисы либо composition root разросся бы адаптерами
   портов; граница «гейтвей знает только интерфейсы» исчезла бы.
2. **Явный `toDto` в каждом порту.** Дублировал бы TypeBox-схемы и создавал
   третий источник формы после схемы и доменных типов.

## Последствия

- `docs/architecture.md` и `server/AGENTS.md` описывают проводку как адаптер,
  а не маппер; обещание «query/body → аргументы сервиса» остаётся для портов,
  где оно реально выполняется (auth, wordle).
- Тест `server/__tests__/wiring-analytics.spec.ts` фиксирует, что дата
  форматируется в проводке, а погода/статистика идут без обёрток.
- B-08 из пула закрыт решением; дальнейшие порты проектируются по этому правилу.
