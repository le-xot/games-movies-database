## Вердикт

**CHANGES REQUIRED.** Один блокер — регрессия видимого UX: на `/pc` заголовок вкладки стал
`«Сетап Лешота Лешота»` (суффикс `«Лешота»` добавляется к заголовку, который уже содержит бренд).
Это подтверждено и в живом браузере на обоих коммитах, и пробой `formatTitle` + `meta`. Остальное
сделано аккуратно: `useTitle` действительно стал единственным владельцем `document.title`, семь
прежних писателей удалены без потери закрытия мобильного меню, `meta.title` есть у всех листовых
маршрутов, back/forward теперь ставит актуальный заголовок, обязательные прогоны зелёные
(включая `typecheck` с холодным кешем `vue-tsc`).

Ниже — блокер B1 и шесть не блокеров (N1–N6); N2 (динамика оценок) нашёл не по диффу, но он
ломает заявленную гарантию батча и заслуживает отдельного решения.

### Блокеры

- **B1. `/pc`: `«Сетап Лешота Лешота»` — суффикс приклеен к заголовку, в котором бренд уже есть.**
  В `router.ts:55` `meta: { title: 'Сетап Лешота' }`, а `router.afterEach` (`router.ts:146-151`) по
  умолчанию добавляет `«Лешота»` (`titleSuffix` не выставлен). Итог: `formatTitle('Сетап Лешота')` →
  `«Сетап Лешота Лешота»`. Прежний `PcPage.vue` писал `document.title` напрямую через `@vueuse`
  `useTitle()` — **без** шаблона, т.е. ровно `«Сетап Лешота»` (проверено и изолированным прогоном
  `@vueuse/core`, и живым браузером на `1f55cd3`).
  Доказательства:

  | Проверка                                                     | parent `1f55cd3`                                   | HEAD `5d999c7`          |
  | ------------------------------------------------------------ | -------------------------------------------------- | ----------------------- |
  | живой браузер, прямой заход `/pc`                            | `«Сетап Лешота»`                                   | `«Сетап Лешота Лешота»` |
  | живой браузер, SPA-клик с главной по «Железяки»              | (отдельно не перепроверял, код тот же `onMounted`) | `«Сетап Лешота Лешота»` |
  | memory-history проба `router.push('/pc')` → `document.title` | —                                                  | `«Сетап Лешота Лешота»` |

  Это нарушает правило кампании «UX не меняется» и портит заголовок вкладки в самом заметном
  месте. Фикс — одна строка: `meta: { title: 'Сетап Лешота', titleSuffix: false }` (то же основание,
  что у главной: в тексте уже есть «Лешота»). Заодно стоит решить судьбу админки — см. N1.
  Примечание: заголовков, где слово «Лешота» уже есть, ровно два — главная (учтена) и `pc`
  (пропущен); остальные (`Игры`, `Советы`, …) корректно получают суффикс.

### Не блокеры

- **N1. Админка меняет заголовок: было `«Админка»`, стало `«Админка Лешота»`.** `router.ts:69`
  `meta: { requiresAdmin: true, title: 'Админка' }` + суффикс по умолчанию. Прежний `AdminPage.vue`
  ставил `title.value = 'Админка'` через `@vueuse` `useTitle()` без шаблона — изолированный прогон
  даёт `«Админка»`. Это тоже изменение UX, но осознанное «приведение к общему формату» выглядит
  допустимым; нужно только зафиксировать решение: либо `titleSuffix: false` (сохранить прежний
  текст), либо записать изменение в ADR/коммит-месседж. Не блокер, потому что страница служебная
  (`PRIVATE_PATHS`, `noindex`), а не пользовательская.
- **N2. Динамический «Оценки {login}» перетирает заголовок уже после ухода со страницы оценок.**
  Проверено настоящим сторожем `useUserRatings` (custom renderer + реальный `useUserRatings`,
  замоканный `/api/ratings`): после данных заголовок `«Оценки Alice Лешота»` — как и задумано;
  но после `router.push('/db/games')` (и после `afterEach`, поставившего `«Игры Лешота»`) watcher
  снова пишет `«Оценки пользователя Лешота»`, потому что при смене маршрута `profileUserId`
  становится пустым, `items` сбрасываются, `profileLogin` → `null`, и `watch([isMine, profileLogin],
  …, { immediate: true })` (`use-user-ratings.ts:60-66`) срабатывает вне своей страницы.
  Это **не регрессия коммита**: `use-user-ratings.ts` в diff не входит, и в parent тот же watcher
  точно так же перетирал заголовок после клика по меню (эмуляция старого `handleNavClick` —
  `updateTitle('Игры')` до `push` — даёт тот же итог). Но батч объявил `useTitle` единственным
  владельцем и оставил ровно это исключение — и оно ломает гарантию «на странице X заголовок X»
  в частом сценарии «оценки → любой другой раздел» (в т.ч. back/forward; там старый код просто
  оставлял устаревший заголовок). Рекомендация: скоупить watcher по маршруту (`if (route.name ===
  'my-ratings' || route.name === 'user-ratings')` внутри колбэка) и добавить ловушку; правка
  на одну строку, но файл вне diff — поэтому отдельной задачей/раундом.
- **N3. dev-guard «маршрут без `meta.title`» всегда красный: warning на каждом запуске dev.**
  `router.ts:189-193` фильтрует `!route.redirect && !route.meta.title`, а `router.getRoutes()`
  отдаёт и родительские layout-записи: `home-layout` (path `/`, есть `children`, нет `redirect` и
  нет `title`) попадает в список. Живой браузер на HEAD подтверждает: в консоли каждого запуска
  `[router] маршруты без meta.title: home-layout`. `db` не попадает (у него есть `redirect`),
  `not-found` тоже. Формально это «работает как написано», но постоянно-красная проверка
  перестаёт быть ловушкой (её просто игнорируют). Фикс: пропускать layout-записи
  (`route.children?.length` или проверять наличие компонента страницы), оставив предупреждение
  только для листовых маршрутов. Проверка ожидаемого списка имён при этом цела: warning'ов
  `[router] отсутствуют маршруты` и `[router] дублирующиеся имена` нет — только строка про
  `home-layout`.
- **N4. Осталась вторая ручка на тот же `document.title`: `updateTitle`.** `stores/use-title.ts:24-26`
  объявляет «совместимый короткий алиас», вызывается ровно из одного места — `use-user-ratings.ts:63`.
  Правило «deletion over accumulation» и DoD батча («старого пути нет») говорят, что каноничный
  `setTitle(text)` должен остаться один: вызов в оценках перевести на `setTitle`, алиас удалить.
  Не блокер: поведение не страдает, дубль чисто гигиенический.
- **N5. `afterEach` игнорирует `failure` (третий аргумент).** В vue-router 5 `afterEach` зовётся и
  для неуспешных навигаций (кроме redirect-источника: при redirect он рекурсивно уходит в
  `pushWithRedirect` до `triggerAfterEach`), поэтому при будущем guard'е, который вернёт `false`
  вместо redirect, заголовок поставится странице, которая не отрисуется. Сейчас все стражи
  `router.ts` только редиректят, так что проявления нет — это hardening-замечание, а не дефект.
  Достаточно `router.afterEach((to, _from, failure) => { if (failure) return; … })`.
- **N6. Тест `formatTitle` не тавтологичен, но не ловит мутацию константы; интеграционного теста
  на `meta → title` нет.** Мутации: заменить тело `formatTitle` на `return text` → 2 теста падают;
  на «всегда добавлять суффикс» → 1 падает (откатывал, спек снова зелёный). Но ожидание в тесте
  интерполирует `APP_TITLE_SUFFIX`, поэтому подмена значения константы (`'Лешота'` → `''`) тест не
  роняет; лучше добавить хотя бы одну литеральную проверку (`expect(formatTitle('Игры')).toBe('Игры
  Лешота')`). Главное: нет теста на фактический маппинг `route.meta.title → document.title`, из-за
  чего B1 и прошёл CI. Простой ловушки — вынести конфиг маршрутов в импортируемый модуль (сейчас
  `router.ts` создаёт `createWebHistory()`, в Bun-тесте не импортируется) и тестом проверить, что
  каждый листовой маршрут имеет `meta.title`, а `formatTitle` от него даёт ожидаемую строку. Для
  этого батча достаточно хотя бы `titleSuffix: false` на `pc` + ручная матрица в отчёте.

Мелочь без номера: в `HomePage.vue` вместе с `@vueuse`-писателем удалили комментарий «та же строка,
что в `backend/src/server/page-meta.ts`…»; теперь литерал главной живёт в `router.ts:49`, а серверный
— в `page-meta.ts:41`, и ничто не мешает им разъехаться (сейчас совпадают). Можно вернуть строчку-
предупреждение к meta главной или покрыть тестом соответствие. Также `NavItem.vue` продолжает
эмитить `select: [name]`, хотя имя больше никому не нужно (в `LayoutHeader` обработчик `closeMobileNav`
аргумент игнорирует) — безвредный остаток.

## Пункт 2. Динамика и порядок

- **`afterEach` не перетирает динамический заголовок** — наоборот, данные ставятся позже и
  выигрывают. Порядок в vue-router 5: `finalizeNavigation` (обновляет `currentRoute`) → `afterEach`
  → рендер/маунт страницы и flush watcher'ов. Проверено харнессом с настоящим `useUserRatings`:
  на `/db/users/7/ratings` после `push` заголовок `«Оценки пользователя Лешота»`, после ответа
  замоканного API — `«Оценки Alice Лешота»`; повторный вызов `setTitle` вручную после навигации
  также не перетирается ничем, кроме данных (это и есть заявленное исключение).
- **Порядок с Pinia безопасен.** `main.ts`: `app.use(pinia)` → `app.use(PiniaColada)` →
  `app.use(router)`; первая навигация запускается уже после установки Pinia, поэтому `useTitle()`
  внутри `afterEach` имеет активную Pinia. Живой браузер подтверждает: приложение поднимается,
  `document.title` ставится на первом заходе, ошибок Pinia нет.
- **N2 — обратное направление ломает гарантию:** при уходе со страницы оценок стор-исключение
  перетирает уже поставленный роутером заголовок (`«Оценки пользователя Лешота»` вместо
  `«Игры Лешота»`); подробно выше. Файл `use-user-ratings.ts` этим коммитом не менялся, поэтому
  не регрессия, но батч F-05 без скоупинга исключения задачу «заголовок из маршрута» закрывает
