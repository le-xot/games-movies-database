```ts

  stop()
```

`finish` объявлен раньше `timer`/`stop` — это **ровно то состояние**, которое ревью 24 описывало как N5 («TDZ-зависимость не видна из кода; сейчас корректно»). **Факт №3 — рантайм корректен (TDZ недостижим).** `finish` вызывается только из двух асинхронных путей: `setTimeout`-колбэка (макрозадача; браузер/Bun не вызывают его синхронно даже при 0 мс) и `watch`-колбэка (Vue по умолчанию `flush: 'pre'`, задание кладётся в очередь и исполняется на микрозадаче, не во время `watch()`; `immediate` не задан). К моменту любого вызова обе константы инициализированы, `ReferenceError` невозможен.

**Факт №4 — семантика таймаута/резолва.** Временная проба (отдельный спек, подменяет `@pinia/colada`/`useApi`/`lib/api` и оборачивает `vue.watch`, чтобы посчитать `stop`/колбэки; удалена после прогона) — **4 pass / 0 fail**, на реальном `useUser` из коммита:

- уже завершённый запрос (`isLoading === false`) — резолв без создания watcher'а (`watchCalls === 0`, <20 мс);
- загрузка → `isLoading=false` — резолв по переходу, watcher снят (`stopCalls === 1`), колбэк вызван один раз;
- «вечная» загрузка при `timeoutMs = 40` — резолв за ~40.3 мс (в окне 35–150), watcher снят `finish`'ем;
- после резолва по таймауту повторные `isLoading true→false` больше не дергают колбэк — watcher снят, двойного `finish`/резолва нет (сам `resolve()` идемпотентен).
