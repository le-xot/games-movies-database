## Пункт 3. Находка: fade-анимация бейджа «Новое» больше не применяется

**Не блокер** (motion-only; раскладка, контент и функции не изменились).

Причина — CSS scoping: `<transition name="fade">` обёртка переехала в `SuggestionItemCard.vue`
(`:101`), а правила `.fade-*` остались в scoped-стиле `SuggestionCard.vue` (`:89-96`). У дочернего
компонента нет своего `<style>`, поэтому бейдж внутри него не получает ни одного `data-v-*`, и
правила родителя (`[data-v-aea75798]`) к нему не применяются. Замеры на живом hover:

| Метрика                                | parent `2085870`                                  | HEAD `e9cd522`                                                      |
| -------------------------------------- | ------------------------------------------------- | ------------------------------------------------------------------- |
| `data-v` на бейдже                     | `data-v-aea75798` (совпадает с селектором правил) | **нет атрибута**                                                    |
| Правил `.fade-*`, матчащихся с бейджем | 2 из 2                                            | **0 из 2**                                                          |
| `getComputedStyle(badge).transition`   | `opacity 0.5s ease`                               | `color/background/border… 0.15s` (класс `transition-colors` бейджа) |
| Задержка удаления бейджа после hover   | **513 ms** (плавное затухание)                    | **166 ms**, прозрачность не меняется (opacity 1) — исчезает рывком  |

Статический DOM и fullPage-скриншоты до hover совпадают, поэтому «DOM 0 / пиксели 0» из тела
коммита верны, но не покрывают анимацию. **Фикс:** перенести `.fade-*` в
`SuggestionItemCard.vue` (`<style scoped>`) и удалить мёртвый CSS из `SuggestionCard.vue`; после —
повторить hover-пробу. Если анимацию решено не сохранять — убрать `<transition name="fade">` и
мёртвый CSS явно, а потерю отразить в теле коммита.
